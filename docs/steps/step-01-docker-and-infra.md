# Step 01 — Docker & Infrastruktur Dasar

## 1. Goal

Membangun fondasi monorepo dan orkestrasi seluruh komponen Botseri dalam satu `docker-compose.yml`:

- Jaringan internal tunggal `botseri-net` (bridge).
- Empat service inti: `botseri-db`, `botseri-dashboard`, `botseri-n8n`, `botseri-waha`.
- Service opsional `botseri-tunnel` di balik profil `tunnel`.
- Tiga volume persisten: `botseri_pgdata`, `botseri_n8ndata`, `botseri_wahadata`.
- Image n8n kustom dengan entrypoint provisioning otomatis (tanpa UI).
- `.env.example` dan generator rahasia.

**Batas step ini:** seluruh image berhasil di-build dan `botseri-db` + `botseri-waha` berjalan sehat. Dashboard belum memiliki endpoint health (dibuat di Step 02), sehingga seluruh stack baru dapat di-`up` penuh pada akhir Step 02.

## 2. Prerequisites

- Docker Engine 24+ (di WSL2 dengan `systemd=true`, atau Docker Desktop WSL2 backend).
- `openssl`, `bash`, `git`.
- Port host `3000` bebas (opsional, hanya binding loopback).
- Repositori berada di filesystem Linux WSL2 (`/home/<user>/...`), **bukan** `/mnt/c/...`.

### 4.2 `.env.example`

Nilai rahasia sengaja dikosongkan. Tidak boleh ada API key LLM, kredensial Google, atau nomor WhatsApp di sini (§4.5).

```dotenv
# ============================================================
# Botseri — Environment Variables (ARCHITECTURE.md §4.5)
# Copy to .env and fill in values.
# Generate secrets: bash scripts/gen-secrets.sh > .env
# ============================================================

# --- Database (required) ---
POSTGRES_USER=botseri
POSTGRES_PASSWORD=
POSTGRES_DB=botseri

# --- Encryption (required) ---
# 32-byte key, base64-encoded. For AES-256-GCM encryption of secrets in DB.
ENCRYPTION_KEY=
# Previous key during rotation (optional)
# ENCRYPTION_KEY_PREVIOUS=

# --- Internal API (required) ---
# Random token for n8n <-> dashboard communication
INTERNAL_API_TOKEN=

# --- Dashboard session (required) ---
SESSION_SECRET=

# --- Setup (optional) ---
```

### 4.3 `scripts/gen-secrets.sh`

Menghasilkan `.env` lengkap dengan rahasia acak. Password database memakai hex agar aman disisipkan ke `DATABASE_URL` tanpa encoding.

```bash
#!/usr/bin/env bash
set -euo pipefail

hex() { openssl rand -hex 32; }

cat <<EOF
# Generated by scripts/gen-secrets.sh on $(date -u +%Y-%m-%dT%H:%M:%SZ)
POSTGRES_USER=botseri
POSTGRES_PASSWORD=$(hex)
POSTGRES_DB=botseri

ENCRYPTION_KEY=$(openssl rand -base64 32)
INTERNAL_API_TOKEN=$(hex)
SESSION_SECRET=$(hex)

PUBLIC_BASE_URL=https://panel.yourdomain.com
TZ_DEFAULT=Asia/Jakarta

WAHA_API_KEY=$(hex)
WAHA_SESSION=default

N8N_ENCRYPTION_KEY=$(hex)

N8N_VERSION=1.64.1
WAHA_VERSION=latest-2026.9.2
CLOUDFLARED_VERSION=2024.10.1

LOG_LEVEL=info
EOF
```

```bash
chmod +x scripts/gen-secrets.sh
bash scripts/gen-secrets.sh > .env
```

> `ENCRYPTION_KEY` dan `.env` adalah satu-satunya salinan kunci master. Simpan terpisah dari backup database (§18.4).

### 4.4 `docker-compose.yml`

```yaml
# Botseri — Docker Compose (ARCHITECTURE.md §4.3)
name: botseri

x-restart: &restart
  restart: unless-stopped

services:
  botseri-db:
    <<: *restart
    container_name: botseri-db
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
    volumes:
      - botseri_pgdata:/var/lib/postgresql/data
    networks: [botseri-net]
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 10

  botseri-dashboard:
    <<: *restart
    container_name: botseri-dashboard
    build: ./dashboard
    env_file: .env
    environment:
      DATABASE_URL: postgresql://${POSTGRES_USER}:${POSTGRES_PASSWORD}@botseri-db:5432/${POSTGRES_DB}
      WAHA_URL: http://botseri-waha:3000
      HOSTNAME: 0.0.0.0
      PORT: "3000"
    depends_on:
      botseri-db: { condition: service_healthy }
    ports:
      - "127.0.0.1:3000:3000"
    networks: [botseri-net]
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://127.0.0.1:3000/api/internal/health"]
      interval: 15s
      timeout: 5s
      retries: 10

  botseri-waha:
    <<: *restart
    container_name: botseri-waha
    image: devlikeapro/waha:${WAHA_VERSION}
    platform: linux/amd64
    environment:
      WAHA_API_KEY: ${WAHA_API_KEY}
      WHATSAPP_HOOK_URL: http://botseri-n8n:5678/webhook/wa-incoming
      WHATSAPP_HOOK_EVENTS: message
      WHATSAPP_START_SESSION: ${WAHA_SESSION}
      WAHA_DASHBOARD_ENABLED: "false"
      WHATSAPP_SWAGGER_ENABLED: "false"
    volumes:
      - botseri_wahadata:/app/.sessions
    networks: [botseri-net]

  botseri-n8n:
    <<: *restart
    container_name: botseri-n8n
    build:
      context: ./n8n-engine
      args:
        N8N_VERSION: ${N8N_VERSION}
    environment:
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_DISABLE_UI: "true"
      N8N_BLOCK_ENV_ACCESS_IN_NODE: "false"
      N8N_DIAGNOSTICS_ENABLED: "false"
      GENERIC_TIMEZONE: ${TZ_DEFAULT}
      TZ: ${TZ_DEFAULT}
      INTERNAL_API_TOKEN: ${INTERNAL_API_TOKEN}
      DASHBOARD_URL: http://botseri-dashboard:3000
      WAHA_URL: http://botseri-waha:3000
      WAHA_API_KEY: ${WAHA_API_KEY}
      WAHA_SESSION: ${WAHA_SESSION}
    volumes:
      - botseri_n8ndata:/home/node/.n8n
    depends_on:
      botseri-dashboard: { condition: service_healthy }
      botseri-waha: { condition: service_started }
    networks: [botseri-net]

  botseri-tunnel:
    <<: *restart
    container_name: botseri-tunnel
    image: cloudflare/cloudflared:${CLOUDFLARED_VERSION}
    command: tunnel --no-autoupdate run
    environment:
      TUNNEL_TOKEN: ${CLOUDFLARE_TUNNEL_TOKEN}
    depends_on:
      botseri-dashboard: { condition: service_healthy }
    networks: [botseri-net]
    profiles: ["tunnel"]

networks:
  botseri-net:
    name: botseri-net

volumes:
  botseri_pgdata:
  botseri_n8ndata:
  botseri_wahadata:
```

Catatan isolasi:

- Tidak ada `ports:` pada `botseri-db`, `botseri-n8n`, dan `botseri-waha`.
- Hanya dashboard yang dipetakan ke loopback host.
- n8n **tidak** menerima `DATABASE_URL` (INV-01).

`n8n-engine/entrypoint.sh`:

```sh
#!/bin/sh
set -eu

DASHBOARD_URL="${DASHBOARD_URL:-http://botseri-dashboard:3000}"
WORKFLOW_DIR="/workflows"
HASH_FILE="/home/node/.n8n/.workflows_hash"
CREDS_TEMPLATE="/home/node/credentials.template.json"
CREDS_DIR="/tmp/botseri-creds"

log() { printf '[botseri-n8n] %s\n' "$*"; }

# 1. Tunggu dashboard siap (liveness + DB + migrasi).
log "menunggu ${DASHBOARD_URL}/api/internal/health"
until curl -fsS "${DASHBOARD_URL}/api/internal/health" >/dev/null 2>&1; do
  sleep 3
done
log "dashboard sehat"

# 2. Render kredensial dari env ke berkas sementara. Tidak ada rahasia di image.
mkdir -p "$CREDS_DIR"
node - "$CREDS_TEMPLATE" "$CREDS_DIR" <<'NODE'
const fs = require('fs');
const path = require('path');
const [templatePath, outDir] = process.argv.slice(2);
const raw = fs.readFileSync(templatePath, 'utf8');
const rendered = raw.replace(/\$\{([A-Z0-9_]+)\}/g, (_, key) => process.env[key] ?? '');
const credentials = JSON.parse(rendered);
credentials.forEach((credential, index) => {
  fs.writeFileSync(path.join(outDir, `cred-${index}.json`), JSON.stringify(credential));
});
NODE

for file in "$CREDS_DIR"/*.json; do
  if ! n8n import:credentials --input="$file"; then
    log "kredensial $(basename "$file") sudah ada atau gagal diimpor; lanjut"
  fi
done
rm -rf "$CREDS_DIR"

# 3. Impor workflow hanya bila hash berubah (idempoten).
if ls "$WORKFLOW_DIR"/*.json >/dev/null 2>&1; then
  CURRENT_HASH=$(cat "$WORKFLOW_DIR"/*.json | sha256sum | awk '{print $1}')
  PREVIOUS_HASH=""
  if [ -f "$HASH_FILE" ]; then
    PREVIOUS_HASH=$(cat "$HASH_FILE")
  fi
  if [ "$CURRENT_HASH" != "$PREVIOUS_HASH" ]; then
    log "hash workflow berubah; mengimpor dan mengaktifkan"
    n8n import:workflow --separate --input="$WORKFLOW_DIR"
    n8n update:workflow --all --active=true
    printf '%s' "$CURRENT_HASH" > "$HASH_FILE"
  else
    log "workflow tidak berubah"
  fi
else
  log "belum ada workflow di ${WORKFLOW_DIR}"
fi

# 4. Jalankan server headless.
exec n8n start
```

`credential.template.json` dan perintah CLI di atas memakai item `[VERIFY]` pada `docs/VERSIONS.md`; jika versi n8n yang di-pin mengubah sintaks, entrypoint harus gagal dengan pesan jelas (bukan diam-diam melewati workflow).

## 5. Definition of Done

Jalankan berurutan dari root repo:

```bash
# 1. Sintaks compose valid dan seluruh variabel terisi
docker compose config --quiet

# 2. Kedua image kustom dapat dibangun
docker compose build botseri-dashboard botseri-n8n

# 3. Database dan WAHA hidup
docker compose up -d botseri-db botseri-waha
docker compose ps

# 4. Database menerima koneksi
docker exec botseri-db pg_isready -U "$(grep '^POSTGRES_USER=' .env | cut -d= -f2)" \
  -d "$(grep '^POSTGRES_DB=' .env | cut -d= -f2)"

# 5. Healthcheck database berstatus healthy
docker inspect --format '{{.State.Health.Status}}' botseri-db

# 6. WAHA merespons dan API key berlaku
# WAHA tidak dipetakan ke host; health memerlukan API key pada versi ini.
docker exec botseri-waha wget -qS -O /dev/null \
  --header="X-Api-Key: $(grep '^WAHA_API_KEY=' .env | cut -d= -f2)" \
  http://localhost:3000/health
```

Kriteria lulus:

- `docker compose config --quiet` tanpa error.
- `docker compose build` selesai tanpa error.
- `botseri-db` berstatus `healthy`.
- `botseri-waha` berstatus `running` dan endpoint `/health` merespons `200`.
- `docker compose up -d` **belum** diharapkan sukses penuh (dashboard health menyusul di Step 02).
